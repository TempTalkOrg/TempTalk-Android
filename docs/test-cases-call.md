## 自动化评估

### 为什么通话测试难以自动化

1. **音视频流验证**：需要验证实际的音频/视频内容是否正常，黑盒 UI 测试无法做到
2. **双端实时协调**：通话需要两台设备精确配合（一端发起、另一端接听），时序要求高
3. **硬件依赖**：麦克风、摄像头、扬声器、蓝牙等硬件交互无法通过 UI 自动化模拟
4. **系统 UI 交互**：来电通知、CallKit 等涉及系统级 UI，Maestro 操控受限

### 可能的半自动化方向

| 方向 | 可行性 | 说明 |
|------|--------|------|
| 通话发起/接听流程 | 中 | 双设备 Maestro 协调，验证 UI 状态（不验证音视频内容） |
| 通话中按钮操作 | 中 | 验证 UI 状态切换（图标变化），不验证实际音频路由 |
| 通话记录生成 | 高 | 通话结束后验证聊天中的通话卡片 |
| 音视频质量 | 低 | 需要专业工具（WebRTC stats、audio loopback），不适合 Maestro |
